# 智能排班助手（Agent Demo）

连锁门店排班 Agent：**对话框式界面（类豆包 / DeepSeek）**，像聊天一样输入一句自然语言即可生成排班，并支持**解释排班原因**与**检查规则冲突**。排班与规则判断完全基于题目提供的 9 条规则（R-01~R-09）和 20 名员工数据，大模型只负责理解自然语言，不会自行“补技能”或编造判断依据。

---

## 一、Agent 访问入口

本地运行（无需联网也可用；未配置 API Key 时自动使用本地解析模式）：

```bash
cd smart-scheduler
pip install -r requirements.txt        # 首次运行前安装依赖
python -m streamlit run app.py
```

浏览器会自动打开 `http://localhost:8501`。Windows 用户也可以双击 `run_demo.bat` 一键启动。

> 首次运行若出现 Streamlit 邮箱引导，直接按回车跳过即可，不影响使用。

## 二、使用说明

界面为**手机风格对话框**：

- 底部输入框输入需求，点击「发送」即可；
- 输入框下方的功能开关可切换「生成排班 / 检查排班」；
- 右上角「📊 数据」可随时查看题目规则与员工数据；
- 首次打开时提供 4 个示例按钮（生成排班、指定人数、检查排班、使用说明），点击即可体验；
- 排班结果以卡片式排班表展示（周末高亮、员工按岗位着色、技能覆盖一目了然），并支持一键下载 CSV。

| 功能 | 输入示例 | 说明 |
| --- | --- | --- |
| 生成排班 | `帮我安排周一到周日的排班，各班按规则最低人数安排` | Agent 解析需求 → 生成排班 → 逐条检查规则 → 解释排班原因 |
| 检查排班 | `周一早班：E01,E02,E03,E04` | 粘贴已有排班，逐条核对 R-01~R-09 与场景约束 |

> 在「生成排班」模式下粘贴排班文本时，助手会自动切换为「检查排班」。

生成排班支持的自然语言要素：

- 日期范围：`周一到周五`、`周六`、`周一、周三、周五` 等；
- 人数要求：`早班4人`、`晚班6人`、`每班5人` 等（未指定时按 R-04 默认值：周一至周五每班 4 人，周六日每班 6 人）；
- 排除员工：`不要安排E03`、`排除E07` 等；
- 未识别到日期时默认按周一至周日处理，并在界面给出提示。

## 三、规则使用说明

Agent 的判断依据全部来自题目数据，不使用大模型常识自由发挥：

1. **规则数据化**：R-01~R-09 逐条在代码中实现为可检查的规则（见 `agent/validator.py`），每一条都有规则编号、状态、风险等级与整改建议。
2. **员工数据化**：20 名员工的岗位、技能、可工作日期、请假、偏好来自题目员工列表（见 `agent/data_loader.py`），排班候选人与技能判断只读取这些字段。
3. **排班求解**：回溯式约束搜索（`agent/scheduler.py`）把 R-01~R-09 与“每人每天最多一个班”作为硬约束，把员工偏好与工作量均衡作为软约束。
4. **技能不补造**：R-09 规定技能必须来自员工数据。若排班中出现数据外员工，校验器直接判为违规（风险高），且无法核实的班次输出「无法判断」。
5. **无法判断即明示**：遇到信息不足、数据外员工或规则无法核对时，Agent 明确输出「无法判断」并建议人工复核，绝不臆测。

## 四、输出格式说明

**排班表**：每个班次输出日期、班次（早班 09:00–17:00 / 晚班 13:00–21:00）、员工列表（含岗位）、人数，可一键下载 CSV。

**规则合规报告**：每条规则输出以下字段：

- 规则编号与内容（R-01~R-09、SC-01）
- 状态：`通过` / `违反` / `无法判断`
- 风险等级：`高` / `中` / `-`
- 涉及员工
- 整改建议
- 归因说明（为什么得出该结论）

**解释**：包括「为什么这样安排」（逐日卡片，可左右滑动查看各班次员工与技能覆盖）、「规则依据」和「员工情况说明」（如请假、可用日期受限、班次未排满的原因）。

## 五、自测样例

以下为本地模式（未使用大模型）实测结果，由 `python scripts/demo_self_test.py` 复现。

**输入**：`帮我安排周一到周日的排班，各班按规则最低人数安排`

**解析结果**：action=`generate`，日期=周一至周日，人数=按 R-04 默认值，排除员工=无。

**输出排班表**：

| 日期 | 早班（09:00-17:00） | 晚班（13:00-21:00） |
| --- | --- | --- |
| 周一 | E01（店长）、E06、E09、E12（4人） | E02（副店长）、E07、E11、E18（4人） |
| 周二 | E20、E01（店长）、E12、E03（值班主管）（4人） | E02（副店长）、E07、E11、E18（4人） |
| 周三 | E04（值班主管）、E06、E09、E20（4人） | E02（副店长）、E07、E11、E18（4人） |
| 周四 | E04（值班主管）、E01（店长）、E06、E12（4人） | E02（副店长）、E07、E11、E18（4人） |
| 周五 | E04（值班主管）、E09、E20、E01（店长）（4人） | E05（高级店员）、E02（副店长）、E07、E11（4人） |
| 周六 | E13、E04（值班主管）、E06、E09、E20、E01（店长）（6人） | E14、E05（高级店员）、E08、E10、E15、E16（6人） |
| 周日 | E13、E04（值班主管）、E06、E09、E20、E17（6人） | E14、E05（高级店员）、E19、E10、E15、E16（6人） |

**规则合规报告**：R-01~R-09、SC-01 与 REQ-01（人数要求）全部 `通过`（每个班次均有店长值守 1 人、饮品制作 ≥2 人、收银 ≥1 人；人数达标；无人超过 5 班/连续工作 5 天；无晚班后次日早班；请假与不可用日期未排班；无数据外员工；每人每天最多一班）。

**检查模式自测**（粘贴以下文本）：

```text
周一早班：E01,E06,E09,E12
周一晚班：E02,E07,E11,E18
周六早班：E01,E04,E06,E09,E13,E20
```

输出：已提供的 3 个班次均满足技能覆盖、人数、可用日期与每日一班要求；因未提供其余班次，R-01~R-07 整体输出「无法判断」并提示补全信息后复核。

## 六、测试

```bash
python -m pytest tests/ -v
```

覆盖：R-01~R-09 与场景约束的通过/违反/无法判断用例；默认场景必须产出完全合规的 7 天排班；自定义人数、排除员工、不可行需求的兜底行为；自然语言本地解析与降级路径。

网页端冒烟测试：`python scripts/smoke_app.py`（用 Streamlit 测试框架模拟对话框输入，分别验证「生成排班」与「检查排班」两条链路）。

## 七、目录结构

```text
smart-scheduler/
├── app.py                  # Streamlit 入口（手机风格对话框界面）
├── agent/
│   ├── types.py            # 数据模型
│   ├── data_loader.py      # 题目规则与员工数据
│   ├── nlu.py              # 大模型意图解析 + 本地模板降级
│   ├── scheduler.py        # 回溯式 CSP 排班求解器
│   ├── validator.py        # R-01~R-09 规则校验与归因
│   └── explainer.py        # 解释生成
├── tests/                  # 单元测试与端到端自测
├── scripts/demo_self_test.py
├── requirements.txt
└── .env.example            # DeepSeek API 配置模板
```

## 八、API 配置（可选）

复制 `.env.example` 为 `.env` 并填入 DeepSeek API Key：

```text
DEEPSEEK_API_KEY=sk-xxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

未配置时自动使用本地解析模式，排班与规则检查功能完整可用。
